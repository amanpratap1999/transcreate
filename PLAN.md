## Problem Statement
Technical creators, DevRel teams, and documentation engineers expanding globally face a critical localization bottleneck. Existing tools (DeepL, Google Translate, Crowdin, Weblate) treat localization as literal, sentence-level string replacement. However, engaging technical blogs, documentation guides, and tutorials rely heavily on cultural analogies, idioms, pop-culture metaphors, and regional humor (e.g., US baseball references, Thanksgiving traffic, local sports) to explain complex abstractions.

When translated literally, these metaphors feel awkward, unintelligible, or alienating to international developers. Conversely, throwing raw Markdown into naive LLM prompts corrupts code blocks, breaks inline syntax, alters frontmatter, and provides zero transparency into what was modified.

## What Makes This Cool
The core delight is **auditable cultural cognition through Full-Stack AST Co-Transcreation**:
1. **Dual AST Extraction:** Decomposes technical Markdown into prose AST nodes (`mdast` via Remark) and embedded code AST nodes (`estree` via Babel/Recast for JS/TS).
2. **Harmonized Co-Adaptation:** When an analogy in prose is adapted (e.g. from an American baseball dugout metaphor to Tokyo conveyor-belt sushi or Indian railway reservations), the variable names, mock domain data, and companion prose inline code references are co-adapted in lockstep across a document-level Symbol Table so code and prose never fall into an uncanny valley.
3. **Programmatic AST Transformation:** Instead of having an LLM hallucinate or rewrite raw code strings, the LLM outputs a structured `symbolTable` and `mockDataSubstitutions`. `recast` traverses the AST programmatically, swapping only verified domain identifiers and mock literals while preserving 100% of the original comments, whitespace, and formatting via `recast.print()`.
4. **Comprehensive Review Workstation:** Generates a zero-dependency, self-contained single-file HTML review app (`{filename}.{locale}.diff.html`). Features:
   - **Dual View Modes:** Split-view with synchronized scrolling vs. GitHub-style Unified inline diff.
   - **Live Rendered Article Preview:** Toggle between diff mode and a publication-ready rendered view with dark/light themes.
   - **In-Browser Review & Approval:** Per-section Accept / Reject controls and 1-click export of the approved `.md` file.
   - **Interactive Intent Drawer with Alternative Metaphors:** Click any cultural adaptation to view why it was substituted, inspect code symbol changes, and pick between alternative regional analogies generated by the model.
5. **Static AST Syntax Validation:** Localized code blocks are validated via static AST re-parsing (`@babel/parser`) to guarantee that transformed code is syntactically well-formed, with a 1-shot LLM repair loop for edge cases.
6. **Zero Formatting Noise:** Uses AST node position coordinates with `magic-string` for surgical replacement, guaranteeing untouched lines, headers, lists, and frontmatter are byte-for-byte identical.

## Constraints
- **Zero Syntax Corruption:** Markdown frontmatter, URLs, anchor links, imported package symbols, and language keywords must remain 100% intact.
- **Zero-Dependency CLI:** Must run directly via `npx transcreate` with zero server, database, or external infrastructure requirements.
- **Single-File Standalone Workstation:** The visual review workstation must be completely self-contained HTML/CSS/JS that works offline without external CDN dependencies or backend servers.
- **Provider Agnostic:** Support hosted frontier models (OpenAI, Gemini, Anthropic) as well as local open-weights models (Ollama, vLLM) via standard OpenAI-compatible endpoints (`@ai-sdk/openai`).
- **V1 Scope Boundary:** Code AST co-adaptation is scoped to JavaScript and TypeScript code blocks in v1. Non-JS/TS code blocks (Python, Go, Rust) remain immutable fences. Static AST parsing replaces dangerous `node:vm` runtime execution.

## Premises
1. **AST Separation & Surgical Splicing:** Technical Markdown cannot be translated as raw text. Code blocks, commands, frontmatter, and URLs must be isolated as immutable tokens. Splicing must use AST node coordinates (`node.position`) via `magic-string` rather than full tree re-serialization, avoiding diff noise.
2. **Harmonized Symbol Table & Inline Code:** Domain identifiers used in prose backticks (e.g. `` `batterCount` ``) must be tracked in a document-level Symbol Table and synchronized via an AST visitor over `inlineCode` nodes in lockstep with code blocks.
3. **Intent Diffs Over Blind Rewrites:** Technical writers will not trust blind AI translations. The primary value lies in the visual "Intent Diff" explaining why analogies were adapted and providing interactive review controls.
4. **Distribution & Zero-Dependency Output:** The tool must ship as a zero-config CLI executable via npx (`npx transcreate ./post.md --to ja-JP`) producing localized markdown and a self-contained interactive HTML review workstation.

## Approaches Considered
### Approach A: Minimal Viable — Token-Shielded Remark Pipeline
- **Summary:** Simple token replacement (`__CODE_1__`) around code blocks and frontmatter before calling an LLM for prose transcreation.
- **Effort:** S (human: ~2 days / CC: ~2 hours) | **Risk:** Low
- **Pros:** Fast to build; zero risk to code blocks.
- **Cons:** Leaves code mock data and variables in the original language, creating a jarring disconnect with new metaphors.

### Approach B: Ideal Architecture — Dual-Tree Prose & Analogy Graph
- **Summary:** Native AST node visitor with an extensible community JSON analogy registry for target locales, outputting localized markdown and an interactive HTML report.
- **Effort:** M (human: ~4 days / CC: ~3.5 hours) | **Risk:** Med
- **Pros:** Preserves AST positions cleanly; builds an extensible community database of idioms.
- **Cons:** Leaves code blocks completely immutable.

### Approach C: Creative Lateral — Full-Stack Prose + Code Co-Adaptation (CHOSEN)
- **Summary:** Co-adapts both narrative analogies and code block variable names/mock data in lockstep, verifying syntax via static AST parsing with format-preserving AST rewriting (`recast`), bundled into a comprehensive HTML review workstation.
- **Effort:** L (human: ~6 days / CC: ~4.5 hours) | **Risk:** Med
- **Pros:** Completely eliminates the narrative/code uncanny valley; surgical AST patching guarantees clean diffs; full review workstation.
- **Cons:** Requires coordinated dual-AST parsing, symbol table synchronization, and client-side review UI state management.

### Module Specifications

#### 1. Markdown AST Parser & Token Splicer (`src/parser/markdown.ts`)
- Parses Markdown with `unified()`, `remark-parse`, `remark-frontmatter`, and `remark-gfm`.
- Uses `unist-util-visit` to extract translatable nodes: `paragraph`, `heading`, `blockquote`, and table `tableCell`.
- Captures start and end character offsets (`node.position`).
- **URL & Asset Shielding:** Prior to transcreation, child `link` and `image` destinations within prose are walked and replaced with opaque placeholders (`__URL_REF_0__`, `__IMG_SRC_1__`). Image `alt` text is marked translatable; URLs remain untouched. Tokens are restored prior to splicing.
- **Inline Code AST Visitor:** Traverses child `inlineCode` nodes. After transcreation, backtick identifiers matching the `symbolTable` are replaced in AST space, avoiding accidental text substring collisions in prose.
- **Surgical Patching:** Uses `magic-string` to replace only the exact byte slices corresponding to modified nodes based on `node.position`.

#### 2. Code AST Co-Adapter (`src/parser/code.ts`)
- Targets JS/TS code blocks (tagged `js`, `jsx`, `ts`, `tsx`). Non-JS/TS code blocks are treated as immutable raw fences.
- Uses `recast` (with `@babel/parser` configured for TypeScript and JSX) to parse code blocks into an AST.
- Extracts candidate domain identifiers:
  - Variable declarations (`VariableDeclarator` id)
  - Object property values and string literals representing mock data
  - Function declaration names for internal tutorial helpers
- **Safety Boundary:** Strict AST guards forbid renaming:
  - Imported package identifiers (`ImportDeclaration`)
  - Member expression properties on external modules (e.g. `express.Router()`, `app.use()`)
  - Standard JavaScript/DOM APIs (`console`, `fetch`, `document`, `Math`)
- **Programmatic AST Rewriting:** Rather than having the LLM generate raw code strings, `src/parser/code.ts` uses `recast.visit()` to programmatically substitute identifiers and string literals matching `symbolTable` and `mockDataSubstitutions`, outputting via `recast.print()`. This guarantees 100% preservation of original formatting, indentation, and comments.

#### 3. Structured LLM Orchestration (`src/transcreate/engine.ts`)
Orchestrates a 2-pass pipeline powered by `@ai-sdk/openai` with strict Zod validation:
- **Pass 1 (Cultural Idiom & Analogy Discovery):**
  Analyzes prose paragraphs alongside candidate code identifiers. Detects regional metaphors, determines target locale equivalents, and creates a unified `DocumentSymbolTable`:
  ```typescript
  export const SymbolTableSchema = z.record(
    z.string(), // original identifier (e.g. "batterCount")
    z.string()  // target identifier   (e.g. "sushiPlateCount")
  );
  ```
- **Pass 2 (Harmonized Transcreation with Alternative Metaphors):**
  Generates localized prose, mock substitutions, code bindings, and alternative regional metaphors:
  ```typescript
  export const IntentCardSchema = z.object({
    id: z.string(),
    sectionIndex: z.number(),
    codeBlockIndex: z.number().optional(),
    associatedSymbols: z.array(z.string()).optional(),
    originalMetaphor: z.string(),
    targetMetaphor: z.string(),
    mismatchReason: z.string(),
    rationale: z.string(),
    alternativeMetaphors: z.array(z.object({
      metaphor: z.string(),
      rationale: z.string(),
      suggestedText: z.string()
    }))
  });

  export const TranscreationResultSchema = z.object({
    localizedSections: z.array(z.object({
      nodeIndex: z.number(),
      localizedText: z.string()
    })),
    symbolTable: SymbolTableSchema,
    mockDataSubstitutions: z.record(z.string(), z.string()),
    codeTransformations: z.array(z.object({
      codeBlockIndex: z.number(),
      associatedSectionIndices: z.array(z.number()) // maps code block to referencing paragraphs
    })),
    intentCards: z.array(IntentCardSchema)
  });
  ```

#### 4. Static AST Syntax Validator & Self-Healing (`src/sandbox/validator.ts`)
- Re-parses transformed code blocks using `@babel/parser`.
- If AST parsing throws a `SyntaxError`:
  - **1-Shot LLM Repair Loop:** Feeds the error message, line number, and original AST back to the LLM:
    *"Code transformation produced SyntaxError: [error] at line [N]. Repair syntax while preserving target analogy [metaphor]."*
  - If repair succeeds, accepts the fixed code.
  - If repair fails, uses `associatedSectionIndices` from the schema to roll back *both* the code block and all companion prose paragraphs to avoid the uncanny valley, tagging the section in the diff report as `flagged_for_human_review`.
- **Zero Execution Risk:** Completely avoids `node:vm` or running arbitrary code on the host machine. Pure static AST parsing guarantees security.

#### 5. Comprehensive HTML Review Workstation (`src/viewer/bundler.ts`)
Compiles a zero-dependency, self-contained single-file HTML review application (`{filename}.{locale}.diff.html`) bundling CSS, client-side state, and JSON data.
- **Dual View Modes:**
  - *Split View:* Side-by-side synchronized scrolling between original and transcreated Markdown.
  - *Unified Diff View:* GitHub-style inline diff displaying word-level insertions and deletions.
  - *Rendered Article Preview:* Switch to a formatted article view displaying fully styled prose, syntax-highlighted code blocks, and styled tables. Includes Dark/Light theme toggle.
- **In-Browser Review & Approval Workflow:**
  - Per-section Accept / Reject action buttons.
  - Rejecting a section immediately reverts both the prose paragraph and companion code block to the original source English.
  - Sticky header with approval progress indicator (e.g., "7 of 9 sections approved").
  - "Approve All" and "Reset" batch controls.
  - **1-Click Markdown Export:** Generates and downloads the final customized `.md` file directly in the browser based on accepted choices.
  - "Copy to Clipboard" button for quick pasting into CMS/PRs.
- **Interactive Intent Drawer:**
  - Clicking any highlighted cultural substitution badge opens a slide-over drawer showing:
    - Source cultural concept & regional mismatch explanation.
    - Target cultural mental model and rationale.
    - **Interactive Analogy Selector:** Displays 1-2 alternative cultural metaphors with a "Select This Analogy" button that dynamically swaps the text in both the diff and preview.
    - Associated code symbol changes and static AST validation status (`PASS - AST Valid`).

#### 6. CLI Entrypoint (`src/cli.ts`)
- Built with `commander`.
- Usage: `npx transcreate <file.md> --to <locale>`
- Flags:
  - `--to <locale>`: Target BCP-47 locale (e.g. `ja-JP`, `hi-IN`, `de-DE`, `es-ES`).
  - `--model <name>`: LLM model override (defaults to environment config).
  - `--dry-run`: Output review workstation without writing the localized `.md` file.
  - `--no-open`: Skip automatic browser opening of the HTML review workstation.
